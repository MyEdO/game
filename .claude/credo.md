# Credo de travail

- **Zéro dette.** Pas de code mort, de deprecated, de rétro-compatibilité, ni de duplication. Rien de différé, rien « hors scope » : on nettoie/refactorise/mutualise au lieu d'empiler.
- **Réutiliser l'existant — le CANONIQUE, pas le voisin.** Avant tout composant/module/op : `docs/primitives.md` + un grep de 2-3 variantes du concept. Étendre le général et le paramétrer plutôt que créer un parallèle ; un patron du code adjacent n'est un modèle que s'il se conforme au canonique.
- **D'abord la COUCHE : système ou scénario.** *Système* (règles des livres) : RAW qui renvoie au MJ (« le MJ décide », fourchette) → règle OPTIONNELLE à valeur maison, paramétrable, taguée `maison`, surchargeable (#390) ; RAW qui ne couvre pas une mécanique nécessaire → LACUNE du système : proposition déduite de l'intention et des règles voisines, puis cérémonie d'arbitrage ; RAW qui définit une mécanique que le code contourne → DETTE, jamais « à notre sauce ». *Scénario* (campagne, aventure) : valeur absente (distance, tarif, durée) ou situation laissée au MJ → ni règle optionnelle ni arbitrage : une valeur d'ADAPTATION que l'orchestrateur ou l'agent d'adaptation décide et trace (doctrines #1993, référence #2001). Une valeur maison n'habille jamais un défaut.
- **La CÉRÉMONIE d'arbitrage est réservée aux RÈGLES DE JEU** : verbatim consigné AU TICKET, avec sa date ; le tag `[entériné AAAA-MM-JJ]` est réservé à l'utilisateur. L'ingénierie révisable (UI/UX, confort, chantier inachevé) s'en passe. Litmus : « deux joueurs pourraient-ils se disputer là-dessus en citant le livre ? » — au doute, cérémonie.
- **Règles GÉNÉRALES, jamais spécifiques.** Corriger la classe entière du problème, pas le cas rencontré. Une garde de synchronisation est un smell : une seule source de vérité.
- **Poison de commentaire, trois familles.** Paraphrase de règle (le commentaire porte la réf nue, la règle vit au Source) ; excuse (« pour l'instant », sans tag `[entériné]`) ; pierre tombale (« déplacé vers X », git porte l'historique). Garde `src/comment-poison-guard.test.ts`.
- **Tu es l'ORCHESTRATEUR.** Des agents codent, tu vérifies TOUJOURS derrière : un agent « fini » ne l'est pas tant que tu n'as pas relu.
- **L'existant est pour beaucoup du POC** : s'il n'atteint pas nos exigences, le supprimer et le refaire — tests compris, réécrits depuis la règle, jamais travestis pour passer.
- **Le poison se corrige DANS LE GESTE — « signaler » n'est pas « corriger ».** Dans ton périmètre : vérifié au Source/code, corrigé dans le MÊME commit. Hors périmètre : issue au gabarit #101, dédupliquée PAR LABEL (`gh api …/labels` fait foi), née sous-issue de sa FAMILLE (les fichiers qu'elle touche), elle-même sous son épique — jamais orpheline ; un lot traite une famille en un train. Un smell mesuré par une garde vit dans le stock de la garde.
- **Un audit se clôt par des GARDES, pas par une purge.** Chaque CLASSE de poison découverte reçoit sa garde mécanique (`scripts/guards/lib/`) dans le même chantier ; le rapport daté porte le COMPTE de trouvailles, qui doit décroître d'audit en audit.
- **Vérifié = prouvé.** Typecheck en sortie COMPLÈTE (jamais `tail`), suite verte, et pour toute UI un scénario réel déroulé dans le navigateur **piloté COMME UN JOUEUR**, console à 0 erreur : clavier et clics réels ; `__wfrp` pour le setup et l'observation, jamais pour déclencher le flux testé (`docs/recette-navigateur.md`).
- **Une référence vivante se met à jour dans le MÊME commit que le code qu'elle décrit** (`npm run docs:check` reste verte). Un doc qu'on ne peut pas maintenir part en `docs/plans/` daté, ou se supprime : jamais du vivant qui ment.
- **L'arbre git est PARTAGÉ** : le `git status` montre le WIP des autres sessions. Jamais attribuer un diff sans preuve (contenu + `git log`), jamais `git add -A` : on committe par chemins.
- **Un ticket porte ses DÉPENDANCES et son ÉTAT MESURÉ.** À l'ouverture, « Bloqué par #N » / « Débloque #N » / « Prérequis partagé avec #N » dans le CORPS (le rétro-lien ne dit pas le SENS). Un blocage EXTERNE déclaré se prouve par une sonde positive collée au ticket (commande + sortie) ; sans elle, c'est révisable, pas un fait.
- **Une issue se ferme CORRIGÉE ou PROUVÉE SANS OBJET** (doublon de #M, constat non reproduit à `<sha>` avec sonde collée, ou décision utilisateur datée). **La fermeture suit la PUBLICATION** : le commit cite `#N` et porte son solde, dont la NATURE fait le `state_reason` ; `.github/workflows/fermetures.yml` ferme après une CI verte sur `main` (à la main : `npm run ops:fermer -- <plage>`). Jamais `gh issue close`. Un écart RAW « noté en follow-up » garde l'issue OUVERTE.
