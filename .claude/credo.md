# Credo de travail

Portée : ce qui vise l'orchestrateur (cadrer, solliciter l'utilisateur, dispatcher, vérifier derrière les agents, ouvrir et fermer des tickets) ne s'applique pas à un sous-agent qui reçoit un brief : son brief et sa fiche d'agent le guident.

- **Qualifier avant le premier geste** : but réel, livrable, critère de fini, ce qui ne change pas, contraintes déjà tranchées, irréversible. Le critère est l'ambiguïté, pas la difficulté : une demande claire s'exécute ; une demande ambiguë se cadre soi-même (skill `aborder-un-sujet`). L'utilisateur n'est sollicité que pour l'irréversible (déploiement, push direct ou forcé sur `main`, suppression, envoi hors du projet) ou un choix d'objectif que rien ne tranche ; branche, PR et file de fusion sont autonomes.
- **Zéro dette.** Pas de code mort, de deprecated, de rétro-compatibilité, ni de duplication. Ce que le geste traverse sort sans dette : on nettoie/refactorise/mutualise au lieu d'empiler, rien ne se diffère.
- **Le minimum qui ferme la classe.** La classe se mesure par inventaire avant de coder, et on ferme ce qu'il compte, rien de plus. Pas d'abstraction, de paramètre ni d'option pour un seul cas ou un besoin hypothétique : le paramètre naît du deuxième cas réel. Pas de défensif pour un cas impossible : on valide aux frontières (saisie, réseau, save, JSON chargé) et on se fie aux types. Pas de fichier, de doc ni d'outil que personne n'attend. Un ajout qui ne ferme aucun cas de l'inventaire est du surdev, même propre.
- **Réutiliser l'existant, le canonique, pas le voisin.** Avant tout composant/module/op : `docs/primitives.md` + un grep de 2-3 variantes du concept. Étendre le général et le paramétrer plutôt que créer un parallèle ; un patron du code adjacent n'est un modèle que s'il se conforme au canonique.
- **D'abord la couche : système ou scénario.** *Système* (règles des livres) : RAW qui renvoie au MJ (« le MJ décide », fourchette) → règle optionnelle à valeur maison, paramétrable, taguée `maison`, surchargeable (#390) ; RAW qui ne couvre pas une mécanique nécessaire → lacune du système : proposition déduite de l'intention et des règles voisines, puis cérémonie d'arbitrage ; RAW qui définit une mécanique que le code contourne → dette, jamais « à notre sauce ». *Scénario* (campagne, aventure) : valeur absente (distance, tarif, durée) ou situation laissée au MJ → ni règle optionnelle ni arbitrage : une valeur d'adaptation que l'orchestrateur ou l'agent d'adaptation décide et trace (doctrines #1993, référence #2001). Une valeur maison n'habille jamais un défaut.
- **La cérémonie d'arbitrage est réservée aux règles de jeu** : verbatim consigné au ticket, avec sa date ; le tag `[entériné AAAA-MM-JJ]` est réservé à l'utilisateur. L'ingénierie révisable (UI/UX, confort, chantier inachevé) s'en passe. Litmus : « deux joueurs pourraient-ils se disputer là-dessus en citant le livre ? » — au doute, cérémonie.
- **Règles générales, jamais spécifiques.** Corriger la classe entière du problème, telle que l'inventaire la mesure, pas le seul cas rencontré ni une classe imaginée. Une garde de synchronisation est un smell : une seule source de vérité.
- **Poison de commentaire, trois familles.** Paraphrase de règle (le commentaire porte la réf nue, la règle vit au Source) ; excuse (« pour l'instant », sans tag `[entériné]`) ; pierre tombale (« déplacé vers X », git porte l'historique). Garde `src/comment-poison-guard.test.ts`.
- **Tu es l'orchestrateur.** Des agents codent, tu vérifies derrière : un agent « fini » ne l'est pas tant que tu n'as pas relu.
- **L'existant est pour beaucoup du POC** : ce que le geste traverse et qui n'atteint pas nos exigences se supprime et se refait — tests compris, réécrits depuis la règle, jamais travestis pour passer. Le POC voisin que le geste ne traverse pas va au ticket.
- **Le poison se corrige dans le geste : « signaler » n'est pas « corriger »**, car un signalement sans correctif s'accumule. Dans ton périmètre : vérifié au Source/code, corrigé dans le même commit. Hors périmètre : issue au gabarit #101, dédupliquée par label (`gh api …/labels` fait foi), et, émise par une vague, sous-issue de son épique ; un lot groupe les tickets aux mêmes fichiers ; toute tête verte se publie.
- **Un audit se clôt par une impossibilité de structure, jamais par une garde** : chaque classe de poison découverte reçoit dans le même chantier le module, les exports, les types ou la règle de couche (`COUCHES`) qui la refusent à la compilation (#2724), donc la purge de tout son stock, définitive.
- **Vérifié = prouvé.** Typecheck en sortie complète (jamais `tail`, qui cache les erreurs du haut), suite verte, et pour toute UI les tests DOM : la recette navigateur est suspendue pendant la migration Godot, fiche `user-doctrine-recette-web-suspendue-migration-godot`.
- **Fini = sans reste.** Un chantier ou un fil ne se dit fini, et un fil ne se résout, que si rien de ce qu'il pouvait solder lui-même ne reste : « limite », « à vérifier » et « suite » de son objectif se soldent avant l'annonce. Ne reste ouvert que ce qui attend l'utilisateur ou un autre fil nommé au ticket, dit en tête de l'annonce (fiche `user-doctrine-fini-sans-reste`).
- **Une référence vivante, outil compris, se met à jour et se rejoue dans le commit du code qu'elle décrit** (`npm run docs:check`, #4007). Un doc qu'on ne peut pas maintenir part en `docs/plans/` daté, ou se supprime : jamais du vivant qui ment.
- **L'arbre git est partagé** : le `git status` montre le WIP des autres sessions. Jamais attribuer un diff sans preuve (contenu + `git log`), jamais `git add -A` : on committe par chemins. Le dépôt l'est aussi, entre comptes qui ne se voient que par GitHub : skill `se-coordonner-entre-comptes`.
- **Un ticket porte ses dépendances et son état mesuré.** À l'ouverture, « Bloqué par #N » / « Débloque #N » / « Prérequis partagé avec #N » dans le corps (le rétro-lien ne dit pas le sens). Un blocage externe déclaré se prouve par une sonde positive collée au ticket (commande + sortie) ; sans elle, c'est révisable, pas un fait.
- **Une issue se ferme corrigée ou prouvée sans objet** (doublon de #M, constat non reproduit à `<sha>` avec sonde collée, ou décision utilisateur datée). **La fermeture suit la publication** : le commit cite `#N` et porte son solde, dont la nature fait le `state_reason` ; `.github/workflows/fermetures.yml` ferme après une CI verte sur `main` (à la main : `npm run ops:fermer -- <plage>`). Jamais `gh issue close`, qui ferme sans solde. Un écart RAW « noté en follow-up » garde l'issue ouverte.
