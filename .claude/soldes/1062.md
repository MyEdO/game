# #1062 — Faux positif de solde-ticket-guard : le drapeau fichier de gh api confondu avec celui de git commit (deny sur toute commande gh api portant ce drapeau, titres de tickets compris) — 2026-10-07

## Constat

Le faux positif venait de la porte PreToolUse, qui lisait le `-F` d'une ligne de commande pour trouver le fichier de message d'un `git commit`. Depuis C2 de #2071 (904a78dda), la porte ne lit plus aucune commande : elle juge le message que git passe au hook `commit-msg` (`scripts/git-hooks/commit-msg.mjs`). Aucune garde du répartiteur ne lit plus `-F`. Le `-F` de `gh api` n'a donc plus rien à confondre.

## VERIFIE

VERIFIE: paire du DoD (verbatim : « `gh api … -F x=@fichier` passe en silence ; `git commit -F fichier` garde son contrôle ») : scripts/hooks/repartiteur.test.mjs:617, `gh api repos/o/r/issues/comments/1 -X PATCH -F body=@corps.md --jq .html_url` rend null au répartiteur réel (lancerHook) ; mutation injectant un refus de ` -F ` dans une garde du REGISTRE → rouge, remise → vert (5bc3a720b). Volet git : scripts/git-hooks/commit-msg.test.mjs:249, vrai `git commit -a -F <fichier>` d'un message sans ticket sur src/ refusé par commit-msg, et :308, message de fermeture sans solde refusé.
