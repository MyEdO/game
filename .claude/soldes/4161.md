# Solde #4161 « `npm run gen` se verrouille sur sa propre sortie périmée quand un dataset est supprimé » — 2026-11-13

NATURE: corrigé

VERIFIE: **cause** : la phase 2 de `npm run gen` (`scripts/gen-espaces.mts`) charge `src/data/index.ts` et `src/data/overrides.ts`, qui importent `src/data/schemas/_racines-vivantes.generated.ts`, module qu'elle rend elle-même, un import par document JSON. Un arbre dont ce module date d'avant la suppression d'un dataset (`combat-stakes.json`, fondu dans `stakes.json` le 2026-11-05) garde un import mort : la phase 2 plante en le chargeant, avant de le rendre, et les outils qui chargent le graphe de la donnée hors de `vite.config.ts` (`hotes/godot/recette.mjs --natif`, `construire.mjs`) plantent de même. L'amorçage de la phase 2 ne remplaçait par son amorce qu'un module absent ou sans un export de l'amorce. Le prédicat de l'amorçage devient `moduleChargeable` : le module porte chaque export de son amorce et chaque document JSON qu'il importe existe encore. **Ligne 1 de la Definition of Done** (un module généré de la phase 2 qui importe un JSON supprimé : `npm run gen` sort 0 et le rend à jour) : sorties à la Réfutation. **Ligne 2** (un test committé couvre le prédicat) : `src/data/schemas/espaces-contrat.test.ts`, « un module de la phase 2 qui importe un document supprimé, ou sans un export de son amorce, n'est pas chargeable ; son amorce et le module courant le sont ».

## Restes
- sur le poste, la reconstruction en fond des hooks git a échoué en silence depuis le 2026-11-05 -> RAS : sa cause est ce verrou, que le correctif lève ; son journal reste sous `.git/hooks-git/reconstruction/`
- les outils de l'hôte Godot ne régénèrent pas les cibles de code à leur démarrage, à la différence de `vite.config.ts` -> RAS : les hooks git les régénèrent à chaque fusion et chaque checkout, ce que le verrou empêchait
