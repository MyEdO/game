## Restes
- GitHub n'exécute aucun pilote de fusion : une PR dont le seul conflit est un conflit d'imports reste « en conflit » sur GitHub jusqu'à la fusion locale de `main`, que le pilote résout alors seul -> #3821
- un clone déjà installé n'a pas le pilote tant que `postinstall` n'y a pas rejoué -> RAS : sans pilote déclaré, git rend sa fusion ordinaire pour `merge=imports` ; le pilote entre au premier `npm install`, ou au premier `npm ci` que le hook `post-merge` joue sur un `package-lock.json` changé
- une liaison que les deux côtés changent différemment, deux imports d'effet différents ajoutés chacun d'un côté, un commentaire dans ou entre les déclarations en conflit restent des conflits -> RAS : replis voulus, ni le sens ni le rang ne se devinent
- fins de ligne CRLF et contenu binaire -> RAS : `.gitattributes` impose `eol=lf` aux textes, et un module de code binaire rend le conflit que git rend sans pilote
