# Solde #2525 (Stocks sous merge=stocks : GitHub n'exécute pas le pilote, la PR est CONFLICTING et le train finit rouge au refus d'entrée en file) — 2026-10-08

VERIFIE: le train reprend désormais une PR que GitHub ne sait pas fusionner, sans geste humain. Une seule voie couvre trois cas : le conflit vu sur la PR AVANT la demande (contrôle en tête de l'étape `file`, avant toute attente de CI de branche), le refus de la demande relu en conflit, et tout rouge de file ATTRIBUÉ à la PR (`G^1` ∈ `origin/main`). Cette voie fusionne `origin/main` sous les pilotes locaux, puis l'étape `docs` régénère les stocks de sites au point fixe (`npm run stocks:regen`, `regenStock.mts --tous`) et les commet (`chore(stocks)`).

Contre-invariant : un conflit résiduel sous pilote reste une fusion ABANDONNÉE, fichiers nommés. Une croissance née de la fusion est refusée par la porte du commit et reste un rouge nommé : le train n'écrit jamais de `CLIQUET:`.

Sonde (c.6065889428) :
- Sur le témoin #2522, la fusion `122e5a6b5` × `d6f062fda` SANS pilote (clone `--shared`, comme le serveur) bute sur `balayages-non-resolus-stock.json` ; AVEC pilote, elle est propre.
- L'union du pilote n'est PAS le point fixe : 432 entrées contre 416, soit 16 périmées nées de la branche. Une reprise qui s'arrêterait à la fusion poussait une tête rouge.
- `npm run stocks:regen -- --check`, joué en vrai : rc=0 en 123 s, 27 stocks à jour.

Preuves de banc :
- `typecheck:fast` 0 erreur ; `test:perimetre` rc=0 (vitest 1481/1481, node 2905/2905).
- Mutations M1 à M11 : chacune rougit au moins un test, et tout est vert après retrait.

## Arbitrages, mesures à l'appui (évaluations d'ingénierie révisables, sans verbatim utilisateur)

- **(a) écartée**, contre #2203 (stocks sortis de git, format sûr à l'union, un fichier par entrée). Un stock est la RÉFÉRENCE d'un cliquet : `ecartsDeStock` compare la mesure au commité. Il porte aussi des champs manuscrits : `lot`/`date`, `quoi`, `preuve`, et des motifs. Et même sans conflit textuel, l'union n'est pas le point fixe (432 contre 416). Le juge de design n'a pas réfuté ce verdict.
- **Tous les stocks régénérés, et non ceux touchés des deux côtés.** Coût mesuré : 137 s pour les 24 modules. Une branche qui ajoute des sites, alors que main améliore un résolveur sans toucher au stock, rend l'union périmée même si un seul côté a touché le fichier. Aucune correspondance stock → module : la découverte se fait sur l'arbre syntaxique (`modulesQuiMesurent`).
- **Tout rouge de file attribué se reprend, plus seulement celui des jobs dérivés.** La file n'admet qu'une tête dont la CI de branche est verte. Le rouge attribué vient donc de l'interaction avec le tronc : la fusion et la régénération le guérissent, ou le font réapparaître en rouge NOMMÉ sur la CI de branche, dans la même borne. `GATES_DES_DERIVES` et `jobsDesDerives` sont supprimés, faute de lecteur.
- **Pas de `--no-commit`** : `bilanDeFusion` ne compte rien sur une fusion automatique, et la fenêtre `MERGE_HEAD` échapperait au `preflight` (juge de design, O2).
- **Une PR hors train reste refusée par GitHub** : c'est le comportement sûr. Les 60 dernières PR fusionnées sont toutes passées par le train.
