# #2451 — relais implicite hors production — 2026-10-07

## Consigne et constat

Consigne utilisateur du 2026-10-07, `.git/suivi/consignes/2451.md`, Geste 3 : « Le défaut PROD ne vaut que pour import.meta.env.PROD. Hors production, sans VITE_RELAY_URL, l'app vise le relais local de npm run relay:dev, ou refuse avec un message nommé en français ».

Avant correction, `relayHttpUrl` rendait l'adresse du Worker Cloudflare sans variable, également en test et en développement. La résolution canonique sert HTTP (`netHostStart`, POST `/rooms`) et WS (`roomWsUrl`, `RoomHost`, `RoomGuest`).

Audit des autres sorties réseau transmis par l'orchestrateur : le relais est la seule adresse de production implicite ; les autres accès passent par `BASE_URL`, des chemins relatifs, les assets ou un fond choisi par l'utilisateur. Cet audit est une évaluation d'ingénierie ; aucune règle WFRP n'intervient ici.

## Changement

`relayHttpUrl` garde `VITE_RELAY_URL` prioritaire et choisit ensuite le Worker uniquement si `import.meta.env.PROD` est vrai, sinon `http://localhost:8787`. Le choix local utilise le port Wrangler de `npm run relay:dev` et laisse la recette coop jouable sans variable. Aucun resolver parallèle, aucune modification de `netFlow` runtime.

La section coop de `docs/recette-navigateur.md` indique les deux commandes locales, l'override et le redémarrage Vite, le défaut du build de production, et le refus avec relais arrêté ou port local fermé. Un override explicite peut viser la production dans tous les modes ; l'invariant hors production porte sur l'absence de cet override.
