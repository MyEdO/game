**Verbatim utilisateur (2026-09-15)** : « C'est absurde ... on a dépêché un agent pour créer un fichier (+ son test, + le lien pour l'appeler) et ça va nous prendre 25 min ? » — dit sur #1768 (`scripts/ops/board.mjs`), où le codeur a mesuré ~12 min de code + test verts (24/24) puis ~13 min de gates imposées par MON brief (lint ~2 min, knip ~4 min, docs:check ~5 min, `test:ops` 220 tests), que `npm run ops:publier` rejoue de toute façon à la publication.

**Why :** les gates sont jouées UNE fois par le train de publication (`ops:publier` : gates → ff → push, justificatif keyé sur la tête). Les faire jouer AUSSI par le codeur double le coût sans ajouter une preuve : le train refuserait le même rouge. C'est l'« empilement de gates » du mandat #1757 (2026-09-14), reproduit par un brief.

**How to apply :** dans un brief de codeur, la section « Gates à jouer » ne contient que (a) le test du fichier livré (`node --test <son test>` / `npx vitest run <ses fichiers>`), (b) l'exécution réelle de l'outil livré en lecture seule (`-- --liste`), (c) `npm run typecheck:fast` si du `.ts` bouge. Lint, knip (`deps:unused`), `docs:check`, suites entières, `docs:build` : au train de publication, une fois, par l'orchestrateur. Si une gate du train rougit, le correctif est un train COURT, pas une gate de plus dans le brief suivant. Voir aussi [[user-doctrine-chantier-outille-sans-reinventer]] et #1738 (coût des gates).

## Local = périmètre seul, la CI joue le reste

Consigne utilisateur relayée par la session game-e9 le 2026-09-17 : « ce sont les opérations `npm` locales (npm ci, typecheck, lint, docs:build, suites) qui font ramer » — ne jouer localement que les tests du PÉRIMÈTRE et laisser la CI jouer les gates. Même jour, cause mesurée au ticket #1784 : `ops:publier --detache` lance le train `detached: true` sans console (`publier.mjs:1041-1045`), donc chaque enfant git/gh/npm (dont la boucle `gh` toutes les 30 s pendant 10 min) ouvre sa propre fenêtre Windows au premier plan.

**Why:** une machine partagée entre plusieurs sessions s'effondre sous deux suites complètes ; la CI de branche (régime #1776) joue déjà typecheck + suite + gates sur chaque publication, la répétition locale n'apporte qu'une contention.

**How to apply:** brief codeur = `npm run typecheck` UNE fois en fin + `npm test -- <fichiers du périmètre>` + `docs:check` + eslint des fichiers touchés ; jamais `npm test` nu ni `npm run gates` localement. Le PÉRIMÈTRE d'un lot inclut ses CLIQUETS : un dataset ou schéma neuf/renommé → `npm test -- src/data` entier (config-id-unique, libelles-guard, maison-sans-source, migrations-type-enveloppe, slots-contrat, structures-contrat… : 9 rouges découverts par la CI de #1716 le 2026-09-18, aucun par les gates locales) ; un fichier de `src/gameIso/**` neuf → `banc-volumique.test.ts` ; un `.test.` réécrit → `comment-poison-guard` + `eslint-ordre-total-et-purete`. Le périmètre commence par l'ARBRE DU FICHIER TOUCHÉ lui-même : au train B de #1343 (2026-09-21, `90b9aa6c0`), `sceneMeshes.ts` (sous `src/gameIso/`) a changé la LONGUEUR du read-set de cuisson, et les portes jouées (`src/data src/state src/ui src/scenes`) excluaient `src/gameIso`. Résultat : `src/gameIso/stage/deps-longueur-constante.test.tsx` était rouge, et son voisin passait À VIDE, découverts deux trains plus tard. Liste le périmètre depuis les LECTEURS du symbole touché (`git grep <symbole>`), jamais depuis une liste de dossiers habituelle. Un fichier de TEST touché a pour lecteurs les gardes de racine `src/*-guard.test.ts` (13 au 2026-09-23 : `vi-mock-isolate`, `tests-sans-horloge`, `catch-vide`, `comment-poison`…) : au train E7b de #1343 (2026-09-23), deux `vi.mock` neufs sont passés « verts » chez le codeur, et `vi-mock-isolate-guard` rougissait ; c'est le juge de diff qui l'a trouvé. Brief codeur = `npx vitest run src/*-guard.test.ts` dès qu'un `.test.` est écrit. ⚠ Le motif ne se développe PAS sous PowerShell : vitest le reçoit comme FILTRE, ne lance AUCUNE garde et sort 0 (mesuré au train E7e, 2026-09-23). Brief : lancer par le tool Bash, ou nommer les 13 fichiers ; au rendu, exiger le compte de fichiers de garde exécutés. Les MIGRATIONS DATÉES sont des lecteurs de tout `scripts/**` qu'elles importent, et elles sont REJOUÉES sur un export de HEAD SANS `node_modules`. Au lot B de #1343 (2026-09-23), E1 a posé `import ts from 'typescript'` en tête de `scripts/guards/lib/importGraph.mjs`, atteint par `l1b-10b` via `build-implemente.mjs` ; une migration neuve (bump 11 → 12) a aussi laissé la précédente « DERNIÈRE » à borne close. Résultat : CI de branche rouge (jobs `migrations` + `build`), aucune porte locale ne l'avait vu. Tout lot qui touche `scripts/migrations/**` ou un module de `scripts/` importé par une migration joue `npm run migrations:replay:head` et `migrations:replay:croissance`. #1784 est sur main depuis le 2026-09-17 (`4cd5d4052`) : `--detache` est de nouveau sûr dès que la BASE du worktree le contient (`git merge-base --is-ancestor 4cd5d4052 <base>`). Voir [[env-charge-machine]].
