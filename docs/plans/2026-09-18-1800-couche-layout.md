## 2. Architecture cible en trois couches

Comme une bibliothèque de style : (1) **tokens** — échelles fermées ; (2) **primitives d'identité** — ce qui a une matière (couleur, bordure, police, rayon, ombre) ; (3) **layout** — ce qui PLACE (pile, rangée, grille, split), sans matière. Un écran COMPOSE (2) et (3), et n'écrit ni CSS d'identité ni style inline (arbitrages A1 et A2, §7).

### 2.1 Couche 1 — tokens (`src/ui/styles/base.css`, bloc `:root`)

Échelle d'ESPACEMENT nommée, DÉRIVÉE de l'histogramme `gap` (les six valeurs dominantes 6/8/4/2/12/16 px = 353 des 521 `gap`, 68 %) :

```css
--sp-2xs: 2px;  --sp-xs: 4px;  --sp-sm: 6px;  --sp-md: 8px;  --sp-lg: 12px;  --sp-xl: 16px;
```

Décision d'ingénierie (révisable, non soumise — credo : la cérémonie est réservée aux règles de jeu) : **10 px (49 sites) et 14 px (17 sites) n'entrent PAS dans l'échelle**. Règle de recalage, la même pour tous les lots : 10 → `lg` si le conteneur est un `.panel`, `md` sinon ; 14 → `lg`. `0` et `auto` restent des valeurs légales sans token.

**Rayons et tailles de police** : l'identité (rayon, police) vit dans les PRIMITIVES (couche 2), inchangées par ce ticket (brief : « primitives d'identité (inchangées) »). Aucun token `--r-*`/`--fs-*` ici : ce serait une refonte de `components.css`, hors de la couche layout. Ce n'est pas un report : la garde (xxi) n'en a pas besoin, elle interdit l'identité en module d'écran quelle que soit sa valeur.

### 2.3 Couche 3 — LAYOUT (couche absente, créée)

**Composants, pas utilitaires** (tranché §8) : un concept d'écran = une primitive. Quatre concepts, liste FERMÉE : **Stack** (pile), **Row** (rangée), **Grid** (grille), **Split** (deux colonnes dont une bornée). Fichier React unique `src/ui/Layout.tsx` (patron `MenuCard.tsx` : plusieurs exports d'une famille), feuille `src/ui/styles/layout.css`.

**Ordre de cascade (tranché)** : `layout.css` s'importe dans `src/ui/styles.css` APRÈS `components.css` (et `tabs.css`), AVANT les modules. Raison mesurée : `.panel { padding:16px }` (`components.css:26-32`) et `.panel.flush { padding:0 }` (`:40-42`) écraseraient tout `padding` d'une primitive de layout importée avant. Corollaire : **aucune primitive de layout ne déclare `padding` sans attribut** — la règle est `.stack[data-pad], .row[data-pad], .grid[data-pad], .split[data-pad] { padding: var(--pad) }` ; sans `pad`, un `<Stack className="panel">` garde le padding du panel ; avec `pad`, `[data-pad]` (0,2,0) bat `.panel` (0,1,0) et, à spécificité égale avec `.panel.flush` (0,2,0), gagne par l'ordre. Prouvé par un `it` du §4.3.

Les valeurs se posent en ATTRIBUTS `data-*`, pas en classes modificatrices : (xiii) compte des NOMS de classe (`classNamesDefined` ignore `[data-*]`), et une règle par pas d'échelle sert les quatre primitives.

```ts
// src/ui/Layout.tsx — signatures
export type Espace = '2xs' | 'xs' | 'sm' | 'md' | 'lg' | 'xl';          // = --sp-*
export type Cassure = 900 | 700 | 560;                                     // breakpoints canon (règle 4)
type Balise = 'div' | 'section' | 'article' | 'nav' | 'header' | 'footer' | 'form' | 'ul' | 'ol' | 'li' | 'fieldset';
// `style` INTERDIT à la compilation sur les quatre primitives (A2) ; le reste (id, role, aria-*, data-testid, onClick…) passe.
type Rest = Omit<HTMLAttributes<HTMLElement>, 'style' | 'className'> & { className?: string };

export function Stack(p: { gap?: Espace /* md */; pad?: Espace; align?: 'stretch' | 'start' | 'center' | 'end';
  rowBelow?: Cassure /* sous la cassure : devient une rangée qui s'enroule */; as?: Balise; children: ReactNode } & Rest): JSX.Element;
export function Row(p: { gap?: Espace /* md */; pad?: Espace; align?: 'center' | 'start' | 'end' | 'stretch' | 'baseline';
  justify?: 'start' | 'between' | 'end' | 'center'; wrap?: boolean /* true */;
  stackBelow?: Cassure /* sous la cassure : devient une pile */; as?: Balise; children: ReactNode } & Rest): JSX.Element;
export function Grid(p: { gap?: Espace /* xl */; pad?: Espace; min?: 'sm' | 'md' | 'lg' /* md — auto-fill minmax(min(240|340|400px,100%),1fr) */;
  cols?: 2 | 3 | 4 /* colonnes FIXES ; exclusif de min */; stackBelow?: Cassure /* 700 si cols */; as?: Balise; children: ReactNode } & Rest): JSX.Element;
export function Split(p: { gap?: Espace /* lg */; pad?: Espace; aside?: 'sm' | 'md' | 'lg' /* sm */; side?: 'start' | 'end' /* start */;
  sticky?: boolean /* la colonne bornée reste visible au défilement */; align?: 'start' | 'stretch' /* start */;
  stackBelow?: Cassure /* 700 */; as?: Balise; children: ReactNode } & Rest): JSX.Element;
// Modificateurs d'ENFANT (attributs typés, à étaler : <h2 {...grow}>) :
export const grow = { 'data-grow': '' } as const;        // prend la place (flex:1 1 auto ; min-width:0)
export const pushEnd = { 'data-push': 'end' } as const;  // se cale au bout de la rangée (margin-inline-start:auto)
export const spanFull = { 'data-span': 'full' } as const; // pleine largeur d'une Grid (grid-column:1/-1)
```

Les deux cassures portent des noms qui disent leur SENS : `stackBelow` (Row/Grid/Split deviennent une pile) et `rowBelow` (Stack devient une rangée) — attributs rendus `data-stack-below` / `data-row-below`.

## 8. Pistes écartées (avec la raison mesurée)

1. **Utilitaires Tailwind-like** (`.gap-2`, `.flex`, `.p-4`…). Un utilitaire n'est pas un concept : « un concept d'UI = une primitive » (2026-09-04). Les props typées sur l'échelle (`gap: Espace`) donnent la même expressivité avec une erreur de compilation au lieu d'une dérive.
2. **CSS-in-JS / styled-components**. Ajoute une dépendance, sort les tokens de `:root` (217 tokens, cliquet (iv)), rend aveugles les parseurs texte de (iv)/(vii)/(ix)/(xiii)/(xx) et de ce plan ; l'identité migrerait dans le TSX, exactement l'inverse du cap « primitives et classes ».
3. **Garder (xii) EN PLUS de (xxi)** (option A1-b, écartée par l'utilisateur). Deux gardes sur deux quantités différentes = une garde de synchronisation (credo).
4. **CSS Modules / `*.module.css` scopés par écran**. Institutionnalise la classe mono-écran, le mal nommé par la doctrine.
5. **Container queries à la place des cassures**. Le canon 900/700/560 est gardé par (xviii) et cité par la charte (règle 4) ; les props `stackBelow`/`rowBelow` le portent sans changer le contrat.
6. **Un module `.css` par primitive de layout** (`stack.css`, `row.css`…). Quatre fichiers de 15 lignes pour une seule couche ; `layout.css` est la couche, comme `components.css` est la couche d'identité.

8. **Garder `.row-flex`/`.panel-grid` comme alias rendus par les composants**. Rétro-compatibilité (credo : aucune) ; deux portes pour un concept.
9. **`Bornee`/`Center` comme 5ᵉ primitive** (max-width 640/760/960).
